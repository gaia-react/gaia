# MSW

[Mock Service Worker](https://mswjs.io/). Intercepts HTTP via Service Worker (browser) or interceptors (Node). One mocking layer for tests, Storybook, and dev.

## Entry points

- Dev: the `msw()` plugin from `msw/vite` in `frontend/vite.config.ts`, plus `virtual:msw` imported by both `frontend/app/entry.client.tsx` and `frontend/app/entry.server.tsx`. With `MSW_ENABLED=true` the dev server mocks browser and SSR requests through that one network. Each entry gates the import on `import.meta.env.DEV`, so production builds drop it. Each entry calls `network.configure({handlers, onUnhandledFrame: 'bypass'})` and then `await network.enable()`.
- `frontend/test/worker.ts` calls `setupWorker(...)` from `msw/browser` for browser-project tests. It is not the dev server's worker.
- `frontend/test/test.server.ts` calls `setupServer(...handlers)` from `msw/node` for the Vitest `node` project.

All three share the handler set from `frontend/test/mocks`. Handler and utility imports come from MSW 3 subpaths (`msw/http`, `msw/utils/<name>`); only `setupWorker` (`msw/browser`) and `setupServer` (`msw/node`) come from their own entry points. The unhandled-request option is `onUnhandledFrame`.

## Worker script

`frontend/public/mockServiceWorker.js` is committed and generated by `msw init`. Regenerate it with `pnpm -C frontend msw:init`, which runs `msw init` against `msw.workerDirectory` in `frontend/package.json`. A `node`-project test fails when the committed worker differs from the one the installed msw generates. Storybook loads the same worker from `public/` through `msw-storybook-addon`.

## Companion packages

`@msw/data` (in-memory DB), `frontend/public/mockServiceWorker.js` (see Worker script). `msw-storybook-addon` is wired into Storybook: stories supply handlers through `parameters.msw.handlers`. See [[Storybook Stories]].
