# Local Working State

`.gaia/local/` holds machine-local working state for GAIA's subsystems. It is gitignored in full, carries no tracked files, and is absent from `.gaia/manifest.json`, so nothing under it is committed or shipped to adopters. Each developer's copy is private to their machine, and subsystems create the subdirectories they need on demand (`mkdir -p`).

Because the folder is invisible to git, residue a subsystem leaves behind never surfaces in a diff and accumulates silently. A SessionStart janitor sweeps the residue whose death is provable; everything else is catalogued here so a reader can tell live state from leftovers.

## Layout

| Path | Owner | Kind | Retention |
|---|---|---|---|

| `plans/ledger.json` | [[GAIA Plan]] | live | per-machine number cache |
| `handoff/`, `forensics/` | [[GAIA Handoff]] / [[Forensics]] | live | drop zones |
| `telemetry/` | [[Cost Data Contract]] | live | an append-only cost ledger (`cost.jsonl`) |
| `harden/declines.json` | `/gaia-harden` | live | one copy shared by every tree, so an operator decline made in a linked worktree suppresses the candidate everywhere and survives the worktree's removal |

A linked worktree's `.gaia/local` is a single symlink to the main checkout's `.gaia/local`, so every path in the table above resolves to one copy rather than forking per tree. `.gaia/state-registry.json` declares each entry's scope, and an entry that has to stay private to one tree gets that isolation from a tree key in its own path rather than from a directory of its own; see [[Worktrees]]. The same linking covers a second, disjoint set: the checkout-root gitignored `.env` / `.env.*` files (every basename matching `.env` or `.env.*`, excluding the committed `.env.example`). Each linked worktree gets `<worktree>/.env` (and any `.env.*`) symlinked to the main checkout's copy, so the worktree's `pnpm dev` and Playwright runs read the same local secrets without a manual copy. These files live at the checkout root, not under `.gaia/local/`, so they aren't rows in the table above.

`telemetry/` also holds a second, maintainer-only ledger beside `cost.jsonl`: `telemetry/audit-respawn.jsonl`, the Code Audit Team spawn oracle's append-only re-spawn breadcrumb ledger, one record per member the digest-marker filter considers. It is shared like its `cost.jsonl` sibling, so every tree contributes to one copy, but it is bounded where that sibling is not: a session-start sweep, separate from the nine janitor sweeps below, age-drops records past a retention window and caps the line count, both knobs floor-clamped. It exists only on a clone that carries the spawn oracle.

A **live** entry is load-bearing state that tooling reads. An **ephemeral** entry is consumed once and then orphaned; its owner is meant to prune it, and the janitor backstops what the owner misses.

## The session-start janitor

`.claude/hooks/local-janitor.sh` runs from the SessionStart hook (`wiki-session-start.sh`) on `startup` and `resume`. It is the side-effect form of a SessionStart hook: it acts on disk and injects nothing into context. It is a backstop, not an owner, so each subsystem still prunes its own residue at its next run. Most of what it does is deletion, and it deletes only residue whose death is provable, which makes it safe to run unconditionally every session. One sweep also reconciles rather than reaps, because a wiki landing leaves behind a stale base branch that no deletion can fix; that sweep is the hook's only network call and its only advance of a branch somebody has checked out, and both are bounded. It sweeps nine things:

- **The wiki landing's local residue.** The wiki landing CLI (`gaia wiki chain finish` / `wiki sync land`) cuts a throwaway `wiki-sync/<date>-<sha>` branch and enables auto-merge with `gh pr merge --auto`, then takes one bounded in-CLI wait. The merge gate routinely outlasts any wait that fits in a single invocation, so on the common path the CLI returns with the local branch still present and the local base branch still behind. This sweep covers both, in four steps. First an existence gate: nothing below runs unless a local `wiki-sync/*` branch is present, so an ordinary session pays nothing. Then a bounded, rate-limited `git fetch --prune` of `origin`, capped by `GAIA_WIKI_FETCH_TIMEOUT_SECONDS` (default 5 seconds, floor 1, ceiling 30; `0` disables the fetch outright) and rate-limited by `GAIA_WIKI_FETCH_MIN_INTERVAL_MINUTES` (default 60, floor 5; `0` removes the rate limit rather than disabling anything). Refs and the object store are shared across every linked worktree, so this fetch's effect is repo-global: a worktree-invoked run updates tracking refs every tree observes. Then a guarded reap of each `wiki-sync/*` branch whose upstream now reads `[gone]`. `[gone]` is not proof of a merge, only that the remote head ref is absent, and a PR closed without merging and then branch-deleted reads identically; so the reap refuses any branch carrying work no remote-tracking ref has, tested by patch id with `git cherry` (the only test that can tell a squash-merged branch from an abandoned one, since a squash leaves the tip unreachable by ancestry either way), and hard-deletes the rest with `git branch -D`. Finally a `--ff-only` fast-forward of the base branch to `origin/<base>`, so the landing's own commit is actually present locally. That step makes no network call of its own and is gated on HEAD being on base, a clean working tree, base having an upstream, and the fetch not having been left in an unknown state; its safety comes from `--ff-only` against base's own upstream, which can only advance base to a commit the remote already has, and it is a checkout-aware merge rather than a bare ref write. The catch-up obligation is durable: a session that cannot complete the fast-forward records it in `.gaia/local/cache/shared/wiki-base-catchup.state` and a later qualifying session retries with no new landing required, and because the obligation is one idempotent fact it collapses to at most one file however many landings occur. A fast-forward that a gate declines is a silent skip leaving base byte-identical; one that is attempted and fails writes a single line to `.gaia/local/cache/shared/wiki-base-catchup.report`, which the drift-check hook drains into the conversation on the next prompt. This sweep is git-scoped, independent of `.gaia/local/`, so it runs before the guard below (a fresh clone can carry an orphaned branch before that directory exists).
- **Orphaned audit markers.** A marker's filename key is a member's own 64-hex **content digest**, not a git tree or commit, so no `cat-file`/`branch --contains` reachability call can ever answer "live" for one; liveness is read off each marker's own JSON body instead, through keep-arms that never recompute a digest. A new-scheme `.ok`/`.refused` marker (filename stem is 64-hex AND the body's `.digest` matches it) is kept when its recorded `tree` (a plain data field written at earn time) is the tree of HEAD, any local branch tip, or any worktree's HEAD (a still-open feature line, or a parallel audit in another checkout), OR when it is still within `GAIA_AUDIT_MARKER_RETENTION_HOURS` (default 72) of its own recorded `audited_at`. The frontend earned marker gets one more chance beyond those two: it is also kept whenever its co-keyed disposition sidecar still holds a still-open receipt (`filed`, or `pending` with `pending_reason: "definitive"`), so a long idle gap between audit rounds can never let a still-open out-of-scope receipt age out from under the [[Audit Disposition and Debt Fix#Seed-forward|seed-forward]] mechanism that reads it. A digest-keyed `audit/<frontend-digest>.dispositions.json` sidecar is kept when its own digest still holds a still-open receipt, or when a same-digest marker survived this same pass by any of the arms above. Everything else is reaped: any old-scheme (pre-digest) marker, any body lacking a `.digest` field, the deleted carry-forward feature's `.carried` family, and the CI-observability `audit/<tree>.progress.log` breadcrumb (a data artifact, never re-keyed as a clearance) are all unconditionally spent residue every session, with no liveness or retention check at all. Once a PR squash-merges, its audited content is no longer the tree of any live branch and each of its markers is spent (unless the retention window or an open receipt still covers it). The digest key is what makes the Code Audit Team's members order-independent (see [[PR Merge Workflow]], Marker key), and it is why this sweep cannot simply ask whether a key is a valid commit or tree: a content digest never is.
- **Completed-but-unswept plan dirs.** A `plans/PLAN-NNN/` (or a colocated `specs/<SPEC-ID>/plan[-N]/`) whose `RUNNING` sentinel names a branch that no longer exists and is not marked `DEFERRED`/`PAUSED`/`PARKED` is a plan that likely merged but whose self-cleanup never ran (an interrupted session). The branch-gone signal alone is not sufficient grounds to act: the janitor hands the directory to `plan-archive.sh` only once the plan's ledger row is confirmed terminal (a spec-less `PLAN-NNN` row at `merged`, or the parent SPEC's row at `merged` for a colocated plan); a non-terminal row leaves the folder in place rather than risking an unrecoverable disposition. `plan-archive.sh` itself keeps a spec-less plan (reduced to `SUMMARY.md` + `cost.json`, `RUNNING` cleared) rather than deleting it outright, gated again there on cost representation and on a consolidated `SUMMARY.md` already existing; a spec-colocated `plan[-N]` subfolder deletes only once the parent SPEC's own `SUMMARY.md` exists. A parked plan is always kept.
- **Stray empty dirs.** Empty directories under `.gaia/local/` are removed with `rmdir`, except the structural drop zones tooling expects to find (`audit`, `cache`, `plans`, `forensics`, `handoff`, `specs`, `telemetry`, and the other roots). `rmdir` cannot remove a non-empty directory, so a content-bearing dir is never at risk.
- **Stale SPEC/react-perf cache artifacts.** SPEC-workflow scratch at the root of `.gaia/local/cache/` (`gate1-*.json`, `draft-*.md`, `spec-session-*.json`, `spec-session-*.lock`, `audit-*/`) and react-perf run dirs (a `<run>/` holding `renders.json`) are reaped once older than 14 days. The window is age-gated rather than reference-checked, and deliberately generous, so a paused multi-day authoring session's live draft is never reaped mid-flight while abandoned drafts and forgotten profiling dumps are still collected. The `spec-session-*.lock` liveness marker rides the same 14-day age gate as its `.json` sibling, so a live session's lock is protected the same way; a stale lock reads dormant and is harmless until this sweep reaps it. The `cache` drop zone itself is kept; only its stale contents go.
- **Merged and abandoned SPEC folders past their retention window.** A `.gaia/local/specs/<SPEC-ID>/` folder whose ledger row is `merged` or `abandoned` is kept in place rather than deleted immediately; this sweep delegates to two age-gated sibling scripts sharing one knob (`GAIA_SPEC_RETENTION_DAYS`, default 30 days). `spec-archive-merged.sh` reaps a `merged` folder once its `merged_at` has aged past the window, its `SUMMARY.md` is present and well-formed (consolidation ran), and its cost is fully represented in `cost.jsonl`. `spec-archive-abandoned.sh` reaps an `abandoned` folder once its `abandoned_at` has aged past the same window and its cost is fully represented, no consolidation gate, since an abandoned draft is never promoted anywhere. Either way, a missing or unparseable timestamp, an unrepresented cost, or a folder still inside the window keeps it in place (fail-closed); this sweep is the SPEC-side counterpart to the plan sweep below.
- **Merged and abandoned spec-less plan folders past their retention window.** A `.gaia/local/plans/PLAN-NNN/` folder whose ledger row is `merged` or `abandoned` is kept in place rather than deleted immediately; this sweep delegates to two age-gated sibling scripts sharing one knob (`GAIA_SPEC_RETENTION_DAYS`, default 30 days), the plan-side counterpart to the SPEC sweep above. `plan-archive-merged.sh` reaps a `merged` folder, already reduced to `SUMMARY.md` + `cost.json` by sweep 3's `plan-archive.sh` delegation, once its `merged_at` has aged past the window, a pending wiki-promote drain is absent, and its cost is fully represented in `cost.jsonl`. `plan-archive-abandoned.sh` reaps an `abandoned` folder once its `abandoned_at` has aged past the same window and its cost is fully represented, no consolidation gate, since an abandoned plan is never promoted anywhere; a dangling wiki-promote drain cache is purged rather than guarded on, since no close flow is ever coming to drain it. Either way, a missing or unparseable timestamp, an unrepresented cost, or a folder still inside the window keeps it in place (fail-closed). No plan row is stamped `abandoned` today: the status is reserved in the ledger vocabulary, but no shipped code path sets it, so the abandoned delegation currently has no candidates to act on.
- **Orphaned merged worktrees.** A GAIA plan/debt worktree under `.claude/worktrees/` whose branch upstream reads `[gone]`, the same upstream-absent signal the wiki-landing sweep above reads, is a reap candidate: a crashed or abandoned session can leave the worktree directory behind after its PR squash-merges, with nothing else left to reclaim it. `[gone]` alone does not prove a merge, only that the remote head ref is absent, and a PR closed without merging and then branch-deleted reads identically, so the two cheap refusals run first (a dirty working tree, or a branch a live `RUNNING` plan sentinel still names, keeps the worktree at no extra cost) and only a surviving candidate pays for the merge-evidence read: its branch's COMBINED diff must reproduce, by whitespace-verbatim patch id, some commit in a bounded scan of `<merge-base>..origin/<base>`. The comparison is over the combined diff rather than per-commit because a squash merge lands the whole branch as one upstream commit, matching none of the branch's own commits once the squash collapses more than one. Every read this evidence needs that cannot be answered keeps the worktree, never reaps it: an unresolvable base or merge base, a failed read of any kind, an empty patch id on a branch that is ahead, and a bounded scan that ends without a match. A candidate the scan declines is memoized under the pair of tips whose movement is exactly what could change the answer, the branch tip and `origin/<base>`'s tip, so the same bounded scan does not repeat every session while neither tip moves; only the negative answer is memoized, so a stale entry can only ever cause a keep, never a reap. Teardown runs inline in the janitor: remove the worktree, delete its now-detached branch, and prune the empty parent directories a slashed worktree name leaves behind. There is nothing to delegate to, because the harness owns creation and removal for a live session while this sweep reaps worktrees no session is in; this is the only place GAIA still removes a worktree. A worktree left `locked ... initializing` by a session killed mid-creation refuses a single `--force`, so the removal retries once with a double `--force` before falling back to a prune, and a reaper that cannot clear a wedged entry never silently stops reaping it. This sweep never age-reaps on its own: there is no session-liveness signal, so an old worktree may still be a live long-running session. It also never touches the current checkout and skips a detached HEAD. The wiki-landing sweep's prune-fetch runs earlier in the same process and makes `[gone]` routinely resolvable, so this sweep fires from a session-start run far more often than it would on its own.
- **Off-pattern outlier residue.** Within a bounded scope, the top level of `.gaia/local/` plus the direct children (maxdepth-1) of `audit/` and `cache/`, every child is put to the state registry (`.gaia/state-registry.json`, the single declaration of what lives under `.gaia/local/` and how each entry is scoped): a child the registry recognizes, either a live entry or a named residue path, is kept silently, and a child it does not recognize is **reported on stderr and left in place**. This sweep never deletes an unrecognized thing, so an entry the registry has not learned about yet is surfaced rather than lost; teaching the registry is the fix, and the report names the path to teach it. OS junk (`.DS_Store`, `Thumbs.db`, `._*`) is the single exception, deleted at any age and never put to the registry at all. When the registry is unusable (no `jq`, no registry file, an unresolvable root) every child counts as recognized, so an inability to consult it can never turn into a deletion. The sweep never recurses below maxdepth-1 and never enters the ledger and self-managing zones, `telemetry/`, `red-ledger/`, `handoff/`, `plans/`, `specs/`, `debt/`, `forensics/`, `harden/`, and the `audit/archived`, `audit/security`, and `audit/comprehensive` subtrees, so a protected directory is kept whole rather than descended into; the one bounded exception looks one level into a `cache/` child for a `renders.json` and only ever keeps. It also never follows a symlinked scope root and never reaps a symlinked entry, so a run from a linked worktree cannot reach through into another checkout's state. The registry is the single answer to "may I reap this?"; the janitor source stays the authoritative home for the sweep's own mechanics rather than a copy here. Two known patterns get their own age-managed arm elsewhere instead of riding this sweep: `audit/*.findings.json` on `GAIA_AUDIT_FINDINGS_RETENTION_HOURS` (default 72h, floor 24, sitting beside sweep 2's `GAIA_AUDIT_MARKER_RETENTION_HOURS` but keyed off plain file mtime rather than a marker body's `audited_at`), and `cache/gh-artifact-pr*.json` on `GAIA_CACHE_ARTIFACT_RETENTION_DAYS` (default 2 days, floor 1), both decided by plain mtime alone. Both knobs are floor-clamped: a non-numeric override falls back to its default, and a below-floor override is raised to its floor.

The sweeps are fail-safe on both sides. Where the janitor deletes, any inability to prove a thing is dead (no git, an unreadable HEAD, an unparseable sentinel) skips that thing. Where it reconciles, a working-tree mutation is not a deletion and that argument does not reach, so the safety comes from elsewhere: every gate is cheap and local, `--ff-only` against base's own upstream can only advance base to a commit the remote already has, a failing gate is a silent skip leaving the index and working tree untouched, and an attempt that was made and failed is reported rather than swallowed. Either way the hook always exits 0, so it can never block a session from starting.

## Deciding by hand

Anything under `.gaia/local/` is safe to delete once its owner is done with it: a spent audit marker for an already-merged PR, a plan directory for a merged or abandoned branch, a `KNOWLEDGE-*.md` report already applied, a gate cache for a merged spec. The append-only ledgers (`red-ledger/observations.jsonl`, `worthiness-ledger/worthiness.jsonl`, `telemetry`), the identity files (`.project-id`, `setup-state.json`), and `.gaia/local/specs/ledger.json` (and the `specs/` store it lives in) are the load-bearing exceptions; deleting the ledger drops per-machine draft-resume state and the local half of SPEC-number allocation.
