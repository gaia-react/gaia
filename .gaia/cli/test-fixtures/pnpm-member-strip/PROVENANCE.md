# pnpm-member-strip fixtures

Inputs and expected outputs for the `pnpm-member-strip` release-scrub transform (`src/release/pnpm-member-strip.ts`). Files end in `.lock.fixture.yaml` and `.workspace.fixture.yaml`, never `pnpm-lock.yaml` or `pnpm-workspace.yaml`, so a `git ls-files` count of the real pnpm files never sees them.

Never edit a golden `expected.*` file by hand. Regenerate the whole case with the method below.

## Golden pairs (pnpm-generated)

Both cases were produced with pnpm 12.7.0 (the root `package.json` `packageManager` version), in a scratch directory outside the repository, by one method:

1. Build the folded workspace (a root importer, a `frontend` member and a `.gaia/cli` member) and run `pnpm install --lockfile-only --ignore-scripts`. That lockfile and its workspace file are `input.lock.fixture.yaml` and `input.workspace.fixture.yaml`.
2. Copy the root `package.json`, the lockfile and the `frontend` member (not `.gaia/cli`) to a second directory, delete the `.gaia/cli` item line from the workspace file, and run `pnpm install --lockfile-only --offline --ignore-scripts` over that same lockfile. The result is `expected.lock.fixture.yaml` and `expected.workspace.fixture.yaml`.

Step 1 used the network once to resolve metadata; step 2 ran offline against the store step 1 warmed. Nothing was trimmed from any pnpm-generated file.

- `synthetic/`: small real packages chosen to cover each pruning shape. `ms` is shared by both members (survives). `semver` resolves to 7.6.0 for frontend and 6.3.1 for the member (only 6.3.1 goes). `debug` is member-only while its `ms` dependency is shared (debug goes, ms stays). `use-sync-external-store` resolves with a member-only `react@17.0.2` peer variant (that snapshot goes, the `packages` entry stays for frontend's variant). The member's `string-width-cjs` alias and `@isaacs/cliui`'s alias dependencies exercise alias edges: `string-width@4.2.3`, reached only through an alias, goes; `strip-ansi@6.0.1`, which frontend also depends on directly, survives. The workspace file carries a comment inside the `packages` list and a setting after it, which pass through.
- `repo-fold/`: this repository's own root `package.json`, `pnpm-workspace.yaml`, `pnpm-lock.yaml`, `frontend/package.json` and `.gaia/cli/package.json` at the commit the transform was written against, folded by adding `.gaia/cli` to the root `packages` list and deleting the CLI's own lockfile and workspace file. Its expected pair, regenerated by step 2, was byte-identical to that commit's root pair. Its lockfile carries an orphan snapshot pnpm keeps (a snapshot no importer reaches), the case a "prune everything unreachable" rule gets wrong.

## Hand-written refusal and no-op inputs

Written by hand on a minimal two-document lockfile; they have no expected output because the transform must refuse them or leave them untouched.

- `unknown-version-document-1/`, `unknown-version-document-2/`: `lockfileVersion: '10.0'` in only the named document.
- `member-without-importer/`: the workspace lists `.gaia/cli`; the lockfile has no importer for it.
- `importer-without-member/`: the lockfile has the importer; the workspace does not list it.
- `missing-snapshot/`: the member importer depends on `debug@4.4.0`, which has no snapshots entry.
- `noop/`: neither the workspace entry nor the importer is present.
